## 适用场景

- 目标市场为欧洲 bidding zone：DE-LU、FR、NL、BE、AT、ES、PT、IT-NORD、NO1-NO5、SE1-SE4、DK1/DK2、FI、PL、CZ、HU
- 目标日是未来 1 天（日前市场）
- 需要分时价格曲线、峰谷判断或负电价预警

## 输入确认

开始前确认四项，缺项按用户偏好补默认值并说明：

1. 市场（market，bidding zone 代码）
2. 目标日期（targetDate，YYYY-MM-DD）
3. 粒度（15min / 1h，欧洲日前自 2025-10 起多为 15min）
4. 用途（纯预测 / 储能 / 可调负荷 / 交易参考）

## 标准流程

1. **历史形态**
   调用 `get_price_history`，取最近 7 天同时段数据。
   - 区分工作日 / 周末
   - 记录负电价与尖峰出现的时段
   - 注意：DE-LU/AT 价格是 CC BY 4.0，其它区商用需确认授权

2. **气象**
   调用 `get_weather_forecast`，重点看：
   - 温度极值 → 采暖/制冷负荷
   - 风速 → 风电出力（北海/波罗的海区域影响大）
   - 辐照 → 午间光伏压价（德国、西班牙、意大利北部）
   - 降水 → 水电与负荷不确定性

3. **负荷与新能源**
   调用 `get_load_forecast`，重点看：
   - 净负荷峰值时段
   - 午间是否出现光伏过剩（duck curve）
   - 晚高峰净负荷爬坡速度
   - 若返回 `isForecast=false`，说明是代理数据，风险里必须标注

4. **模型预测**
   调用 `run_price_model`，拿到 P10/P50/P90。
   **这是唯一的数字来源。**

5. **规则校验（按需）**
   若涉及负电价、偏差考核、报价上下限，调用 `search_market_rules`。

6. **尾部检查**
   如果 P50 出现负值或超过历史 95 分位，转 `negative-price-diagnosis` 技能复核。

## 输出要求

- 先给结论：均价、最高、最低、峰谷窗口。
- 再给驱动：天气 / 负荷 / 新能源 / 检修 / 节假日。
- 必须给风险：模型误差、数据缺失、极端天气、跨境输电。
- 置信度只能是 low / medium / high，并说明理由。
- 数字单位统一为 EUR/MWh。

## 禁止

- 禁止用「通常」「大概」给出未经模型计算的具体数字。
- 禁止跳过 `run_price_model` 直接给价格。
- 禁止把 P50 说成确定值。
- 禁止忽略负电价窗口。

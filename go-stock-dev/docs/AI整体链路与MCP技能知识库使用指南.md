# AI 整体链路与 MCP、技能、知识库使用指南

# 一、AI 整体流程链路

先不提具体代码，从“用户发起请求”到“AI 给出答案”看，整个链路可以分成 8 段：

```text
用户提问
  ↓
1. 请求进入
  ↓
2. 选择模型 / 模式 / 提示词 / 技能 / 图片 / 记忆
  ↓
3. 组装系统上下文
  ↓
4. 判断任务复杂度，选择执行模式
  ↓
5. 装配工具与外部能力
  ↓
6. 模型循环：思考 → 调工具 → 看结果 → 再思考
  ↓
7. 输出答案
  ↓
8. 事后沉淀：归档、记忆、推荐保存、事实校验、反思
```

---

## 1. 请求进入

AI 请求可能来自多个入口：

| 入口 | 典型场景 |
|---|---|
| 全页 AI 对话 | 复杂分析、连续追问 |
| 悬浮 Agent 助手 | 看行情时随手提问 |
| 个股页 AI 分析 | 单只股票分析 |
| 市场资讯 AI 总结 | 总结当日市场、新闻、机会 |
| 每日复盘 | 收盘后自动复盘 |
| 盘前策略 | 开盘前自动生成策略 |
| 提示词回测 | 批量验证提示词选股效果 |
| 飞书机器人 | 在飞书里直接问 AI |
| 独立 Web 助手 | 浏览器访问 |
| 定时任务 | 到点自动执行 AI 分析 |

这些入口最终都会进入同一套“AI 对话中后段链路”，区别只在于：

- 用哪个模型；
- 用哪个提示词；
- 是否带历史记忆；
- 是否带图片；
- 是否允许调用工具；
- 结果推送到哪里。

---

## 2. 请求预处理

用户发一句话后，系统先确定这些参数：

- **AI 配置**：使用哪条模型服务；
- **Agent 模式**：自动 / 快速 / 规划 / DeepAgents；
- **系统提示词**：默认人设、用户模板，还是技能全文；
- **用户提示词模板**：有些入口会附带；
- **是否开启思考模式**；
- **是否开启多轮记忆**；
- **是否携带图片**；
- **是否选择了技能**；
- **当前会话 ID**。

这一步决定了后面“带什么上下文、给什么工具、走什么执行模式”。

---

## 3. 组装系统上下文

系统会把多段内容拼成一个完整的“AI 工作说明”，大致包括：

1. **角色设定**
   - 默认是资深股票投资大师；
   - 如果用户选了提示词模板，就用模板；
   - 如果用户选了技能，技能正文会覆盖角色设定。

2. **硬性规则**
   - 涉及行情、财务、新闻等具体数字，必须调用工具；
   - 不允许凭记忆编造；
   - 工具返回空数据或错误时，要明确告诉用户；
   - 遵守合规边界。

3. **当前环境**
   - 当前时间；
   - 全球市场状态；
   - 提醒历史对话里的价格可能已过时。

4. **项目指令**
   - 如果项目目录有 `.go-stock.md` 或 `AGENTS.md`，会读取并注入。

5. **用户画像**
   - 用户偏好、关注市场、持仓风格、交易习惯等。

6. **自进化内容**
   - `SOUL.md`：行为规则；
   - `MEMORY.md`：长期记忆；
   - 最近经验；
   - 与当前问题相关的历史问答。

7. **历史对话**
   - 开启记忆时，会带最近若干轮；
   - 会根据模型上下文窗口自动裁剪，避免超长。

8. **当前问题**
   - 如果用户选了技能，还会在问题前加一段“本次必须使用该技能”的激活说明。

---

## 4. 判断任务复杂度，选择执行模式

系统会根据问题内容判断走哪种模式：

| 模式 | 适合场景 | 工作方式 |
|---|---|---|
| 快速模式 | 查股价、查新闻、单只股票简单分析 | 模型直接决定调哪个工具，调完回答 |
| 规划模式 | 多股票对比、条件选股、复杂分析 | 先拆任务计划，再逐步执行，最后汇总 |
| DeepAgents | 行业深度研究、全维度个股研报、复杂多步任务 | 可拆 TODO、可派子 Agent、可读写文件、可执行命令、可自动加载技能 |
| 自动模式 | 日常使用 | 系统按问题复杂度自动选上面三种 |

一般规律：

- 简单查询 → 快速模式；
- 多步骤、多标的、综合分析 → 规划模式；
- 超复杂研究、需要技能/文件/代码能力 → DeepAgents。

---

## 5. 装配工具与外部能力

这是 AI 能力差异最大的地方。系统不是把所有工具一次性塞给模型，而是按需装配。

### 5.1 内置工具

按问题类型选择，例如：

- 问股价 → 行情、K 线、财务工具；
- 问新闻 → 新闻、公告、研报、政策工具；
- 问选股 → 条件选股、板块、ETF、资金流工具；
- 问龙虎榜 → 龙虎榜、游资、席位工具；
- 问自选/操作计划 → 自选、分组、交易记录、操作计划工具；
- 问加密 → 币安、OKX 工具。

### 5.2 MCP 工具

只有当问题、提示词或技能声明可能用到某个 MCP 服务器时，才加载对应工具。

### 5.3 知识库与长期记忆工具

知识库检索、统一检索、长期记忆检索、用户画像工具通常始终可用，因为任何问题都可能引用。

### 5.4 技能

- 用户用 `/` 手动选的技能，直接注入；
- DeepAgents 模式下，AI 可根据技能描述自己决定是否加载某个技能；
- 技能如果绑定了 MCP 服务器，会连带加载对应工具。

---

## 6. 模型循环：思考 → 调工具 → 看结果 → 再思考

这是 AI 真正“干活”的阶段。

典型过程：

```text
模型看到问题和上下文
  ↓
判断需要什么数据
  ↓
调用一个或多个工具
  ↓
系统执行工具，把结果返回给模型
  ↓
模型判断数据够不够
  ├─ 不够：继续调工具
  └─ 够了：整理成最终回答
```

在 DeepAgents 模式下，还可能变成：

```text
拆解任务 → 写 TODO → 派子 Agent → 子 Agent 调工具
  → 汇总结果 → 检查是否完成 → 再补充 → 输出
```

同时系统会做很多保护：

- 限制单轮工具调用次数；
- 相同只读工具同轮不重复调用；
- 网络抖动自动重试；
- 工具报错不会直接中断，而是把错误告诉模型，让它换方法；
- 工具结果太长会截断或摘要；
- 对话太长会自动压缩历史；
- 用户可随时中断；
- 前端能看到“正在规划 / 正在调用工具 / 正在执行”等进度。

---

## 7. 输出答案

模型最终输出 Markdown 回答。

系统会边生成边推送给前端，因此用户看到的是流式输出，而不是等全部生成完才显示。

不同入口的展示方式不同：

- 全页对话：聊天气泡；
- 悬浮助手：浮动面板；
- 飞书：卡片或图片；
- 每日复盘/盘前策略：报告页面；
- 定时任务：写入数据库并推送事件；
- 独立 Web：浏览器页面。

---

## 8. 事后沉淀

回答完成后，系统还会做几件事：

1. **归档分析报告**
   - 保存到按日期分的 `memory` 目录；
   - 同时进入“AI 分析报告”列表。

2. **写入长期记忆**
   - 把问题和回答切片、向量化，存入长期记忆库；
   - 下次类似问题可以召回。

3. **保存 AI 推荐**
   - 如果回答里包含股票推荐，自动保存推荐记录；
   - 用于推荐列表、预警、回测。

4. **事实校验**
   - 如果回答里出现股价、百分比、市盈率等金融数字，但本轮没有成功调用工具，会给出提醒。

5. **反思与经验沉淀**
   - 检测回答是否存在不确定表述、纠错、用户情绪等；
   - 把经验写入 `LEARNINGS.md`；
   - 严重问题写入 `MEMORY.md`。

6. **反馈学习**
   - 用户点赞/点踩；
   - 负面反馈会触发用户画像纠正学习。

---

## 9. 一个完整例子

用户问：

> 用我的“龙头战法”技能，结合知识库里最近的半导体研报，分析今天龙虎榜里哪些票值得关注，最后把结论发到飞书群。

系统大致会这样走：

1. 识别到用户显式选择了“龙头战法”技能；
2. 加载技能正文，作为本次分析的方法论；
3. 发现“知识库”相关意图，允许调用知识库检索；
4. 发现“龙虎榜”意图，加载龙虎榜工具；
5. 发现“发到飞书群”，判断可能需要飞书 MCP；
6. 先检索知识库中的半导体研报；
7. 再查当日龙虎榜、游资、席位数据；
8. 按龙头战法的方法论分析；
9. 调用飞书 MCP 发送结论；
10. 回答完成后归档、写长期记忆、保存推荐记录。

这就是“技能 + 知识库 + 内置工具 + MCP”的组合链路。

# 二、MCP 的具体导入与使用方法

## 1. MCP 是什么

MCP 可以理解为：

> **给 AI 接外部工具的标准接口。**

比如：

- 飞书机器人 MCP：AI 可以发飞书消息；
- 钉钉 MCP：AI 可以发钉钉；
- 数据库 MCP：AI 可以查外部数据库；
- 企业 API MCP：AI 可以调用公司内部接口；
- 浏览器/搜索 MCP：AI 可以查外部网页。

内置工具解决“股票数据”问题，MCP 解决“外部系统和自定义能力”问题。

---

## 2. 导入前准备

你需要先有一个可用的 MCP 服务，通常包括：

- 服务地址 URL；
- 传输类型：`StreamableHTTP` 或 `SSE`；
- 鉴权方式：
  - 无鉴权；
  - 静态 Header，例如 `Authorization: Bearer xxx`；
  - OAuth 2.1；
- 如果需要环境变量，提前准备好，例如：
  - `FEISHU_TOKEN`
  - `DING_TOKEN`

---

## 3. 导入步骤

### 入口

左侧导航：

> **MCP 服务**

或者：

> **深入研究 → MCP 服务管理**

### 步骤 1：新增服务器

填写：

| 字段 | 说明 |
|---|---|
| 名称 | 建议写清楚用途，例如 `feishu-bot`、`company-api` |
| 描述 | 帮助 AI 理解这个服务器能干什么 |
| URL | MCP 服务地址 |
| 类型 | `streamable-http` 或 `sse` |
| 命令/参数 | 预留字段，当前主要走 HTTP |
| 启用 | 打开 |

### 步骤 2：配置鉴权

#### 方式 A：静态 Header

适合 API Key / Token 场景。

例如：

```text
Authorization: Bearer sk-xxx
X-api-key: xxx
```

Header 值支持变量：

| 变量 | 作用 |
|---|---|
| `{{env.FEISHU_TOKEN}}` | 从环境变量读取，避免明文入库 |
| `{{sessionId}}` | 当前会话 ID |
| `{{uuid}}` | 每次请求生成新 UUID |

#### 方式 B：OAuth 2.1

适合支持标准 MCP OAuth 的服务。

操作：

1. 鉴权方式选 OAuth 2.1；
2. 保存；
3. 点击“授权”；
4. 浏览器完成登录授权；
5. 系统自动保存加密凭证；
6. access token 快过期时自动刷新。

### 步骤 3：测试连接

点击“测试连接”。

系统会：

1. 连接 MCP 服务；
2. 拉取工具列表；
3. 保存每个工具的名称、描述、参数结构；
4. 返回类似：

```text
连接成功！发现 3 个工具：send_message、query_board、push_notice
```

状态含义：

| 状态 | 含义 |
|---|---|
| 可用 | 连接和工具发现都成功 |
| 未测试 | 还没测过 |
| 未授权 | 鉴权失败 |
| 不可用 | 连不上或没有工具 |

### 步骤 4：启用

必须保持“启用”状态，工具才会进入 AI 可调用范围。

---

## 4. 使用方法

### 方式 1：自然语言直接使用

在 AI 对话里直接说：

> 把这份分析结论发送到飞书群。

> 查一下公司 MCP 里的客户数据。

> 用 feishu-bot 发一条消息给测试群。

系统会：

1. 判断问题是否与某个 MCP 服务器相关；
2. 如果相关，加载该服务器的工具；
3. 让模型决定调用哪个工具；
4. 执行后把结果返回给模型；
5. 模型整理最终回答。

### 方式 2：点名服务器

提问里带上服务器名称，命中率更高。

例如服务器叫 `feishu-bot`：

> 用 feishu-bot 把这个结论发到群里。

### 方式 3：通过技能绑定

如果某个技能天然依赖某个 MCP 服务器，可以在技能里绑定。

例如“每日复盘推送”技能绑定飞书 MCP。

这样用户选择该技能时，系统会自动加载飞书工具，不需要每次点名。

### 方式 4：DeepAgents 动态检索

DeepAgents 模式下，MCP 工具会进入动态工具池。

AI 会先判断任务需要什么工具，再检索并加载对应工具。

---

## 5. 注意事项

1. **不是所有 MCP 工具都会每轮加载**
   - 为了节省上下文，只有相关时才加载。
   - 所以问题里点名服务器或工具，能提高命中率。

2. **服务器必须启用**
   - 关闭后 AI 不再加载其工具。

3. **鉴权失败先看状态**
   - `未授权`：检查 Header、环境变量或 OAuth。
   - `不可用`：检查 URL、网络、服务端是否正常。

4. **工具描述要写清楚**
   - 工具描述越清楚，AI 越容易判断什么时候调用。

5. **MCP 适合“动作”，不适合“资料”**
   - 发消息、查外部系统、调用 API → MCP。
   - 上传研报、笔记、规则文档 → 知识库。

# 三、技能的具体导入与使用方法

## 1. 技能是什么

技能可以理解为：

> **一套可复用的专业方法论 + 工作流 + 输出规范。**

例如：

- 龙头战法；
- 打板策略；
- 趋势跟随；
- 财报分析框架；
- 每日复盘模板；
- 行业研究方法。

技能不是普通提示词，它更像是“让 AI 按专家流程工作”的说明书。

---

## 2. 技能的文件结构

一个技能就是一个文件夹：

```text
skills/
└── 龙头战法/
    ├── SKILL.md
    ├── scripts/
    │   └── some-script.sh
    └── references/
        └── example.md
```

其中 `SKILL.md` 必须有。

格式大致是：

```markdown
---
name: 龙头战法
description: A股超短线龙头股识别与跟踪策略，覆盖情绪周期、连板高度、断板处理
---

## 你的任务
你是一名专注 A 股超短线的游资风格交易顾问……

## 情绪周期定位
……

## 纪律铁律
……
```

关键点：

- `name`：技能名称；
- `description`：一定要写清楚适用场景，AI 自动选择主要靠它；
- 正文：完整的方法论和输出要求；
- `name` 和 `description` 必须是字符串，不要写成数组。

---

## 3. 导入方式

### 方式 1：从技能广场导入（推荐）

入口：

> 深入研究 → 技能管理 → 技能广场

步骤：

1. 浏览或搜索技能；
2. 查看技能详情；
3. 点击“导入”；
4. 系统下载技能包并解压到本地 `skills/` 目录；
5. 新对话即可使用。

注意：

- 部分技能是 VIP 专属；
- 导入后就是本地副本，广场删除分享不影响你；
- 导入时会校验 `SKILL.md`、拦截路径穿越、限制解压体积。

### 方式 2：导入本地 zip 技能包

入口：

> 深入研究 → 技能管理 → 导入技能包

步骤：

1. 选择 `.zip`；
2. 系统解压到 `skills/`；
3. 校验目录和 `SKILL.md`；
4. 成功后出现在技能列表。

### 方式 3：手动创建

直接进入程序目录：

```text
<go-stock 程序目录>/skills/
```

新建一个文件夹，例如：

```text
skills/我的复盘方法/
```

在里面创建 `SKILL.md`，写好 frontmatter 和正文。

保存后，新开一轮对话即可使用。

### 方式 4：用技能管理器编辑

技能管理里可以直接：

- 查看技能列表；
- 查看文件；
- 编辑 `SKILL.md`；
- 新建/修改/删除技能文件；
- 启用/禁用；
- 导出技能包。

---

## 4. 使用方法

### 方式 1：斜杠指令手动选择

在 AI 对话输入框输入：

```text
/
```

会弹出技能菜单。

操作：

- 搜索技能名；
- 回车选择；
- 可多选；
- `Esc` 关闭；
- 选中后随消息一起提交。

效果：

- 技能正文会覆盖系统提示词；
- AI 必须按该技能的方法论分析；
- 会附加“技能激活纪律”，防止 AI 用泛泛分析替代；
- 所有 Agent 模式都支持。

适合：

> 我今天明确想让 AI 按“龙头战法”分析。

### 方式 2：DeepAgents 自动选择

DeepAgents 模式下，系统会把可用技能列表交给 AI。

AI 根据：

- 技能名称；
- 技能描述；
- 当前问题；

自主判断是否加载某个技能。

例如用户问：

> 帮我用情绪周期和连板高度分析一下今天的短线市场。

AI 可能自动加载“龙头战法”技能。

适合：

> 我不想手动选，让 AI 自己挑合适的方法论。

注意：

- 自动选择目前主要看 DeepAgents 模式；
- 技能描述写得越清楚，自动选择越准。

### 方式 3：技能绑定 MCP

如果技能需要外部工具，可以在技能配置里绑定 MCP 服务器。

例如：

- “飞书推送”技能绑定飞书 MCP；
- “企业数据查询”技能绑定公司 API MCP；
- “网页研究”技能绑定搜索 MCP。

效果：

- 技能触发时，系统自动加载对应 MCP 工具；
- 不需要用户在问题里反复点名服务器。

### 方式 4：技能附带脚本和资料

技能目录可以带：

- `scripts/`：脚本；
- `references/`：参考文档；
- 其他资源文件。

DeepAgents 模式下，AI 可以按需读取这些文件，而不是一次性全部塞进上下文。

---

## 5. 注意事项

1. **技能是“方法论”，不是“资料库”**
   - 想让 AI 查你的研报 → 用知识库。
   - 想让 AI 按某种方法分析 → 用技能。

2. **描述决定自动选择命中率**
   - 不要只写“股票分析”；
   - 要写清楚适用场景、分析对象、输出形式。

3. **格式错误会被跳过**
   - frontmatter 写错、字段类型不对，该技能可能不生效；
   - 但不会影响其他技能。

4. **建议新开对话验证**
   - 修改技能后，新开一轮对话最稳妥。

5. **技能可以组合**
   - 可以同时选多个技能；
   - 但技能之间方法论冲突时，AI 可能执行不稳定，建议一次只选一个主技能。

# 四、知识库的具体导入与使用方法

## 1. 知识库是什么

知识库可以理解为：

> **你主动喂给 AI 的私有资料库。**

适合放：

- 研报；
- 财报；
- 行业笔记；
- 交易规则；
- 公司资料；
- 复盘总结；
- 自己的分析框架文档。

AI 回答时可以先检索这些资料，再基于资料回答。

知识库和长期记忆的区别：

| 类型 | 内容来源 | 谁维护 |
|---|---|---|
| 知识库 | 你上传的文档 | 你主动维护 |
| 长期记忆 | AI 历史问答 | 系统自动沉淀 |

两者可以在统一检索里一起查。

---

## 2. 创建知识库

入口：

> 研究中心 → 知识库管理

步骤：

1. 点击“新建知识库”；
2. 填写名称；
3. 填写描述；
4. 选择 AI 服务；
5. 选择 embedding 模型；
6. 创建。

注意：

- 每个知识库独立绑定 AI 服务和 embedding 模型；
- **创建后不建议修改 embedding 模型**，否则新旧向量维度可能不一致；
- 如果不知道选什么，先用默认的 `text-embedding-3-small` 或供应商推荐的 embedding 模型。

---

## 3. 导入资料

### 方式 1：直接粘贴文本

适合：

- 一段研报；
- 一篇笔记；
- 一条规则；
- 临时资料。

步骤：

1. 进入知识库；
2. 点击“添加文档”；
3. 粘贴文本；
4. 保存。

### 方式 2：上传文件

支持：

- `.txt`
- `.md`
- `.markdown`

不支持：

- `.pdf`
- `.docx`
- `.doc`

如果资料是 PDF/Word，先转成文本或 Markdown。

步骤：

1. 选择知识库；
2. 点击“上传文件”；
3. 可多选；
4. 系统异步向量化；
5. 页面显示进度。

### 方式 3：批量导入

可以一次上传多个文件。

系统会：

1. 逐文件读取；
2. 自动切片；
3. 调用 embedding 模型；
4. 写入向量库；
5. 显示成功/失败数量。

单个文件失败不会影响其他文件。

---

## 4. 知识库内部怎么处理资料

导入后，系统会做三件事：

### 第一步：文本清洗

统一换行符、去掉 BOM、压缩空行。

### 第二步：切片

按 Markdown 标题、段落、行、句号等逐级切分。

大致：

- 每片约 500 字；
- 相邻片段重叠约 60 字；
- 太短的片段会合并。

这样做的目的：

- 片段太大，检索不精准；
- 片段太小，语义不完整；
- 重叠可以避免关键句被切断。

### 第三步：向量化

把每个片段交给 embedding 模型，生成向量。

之后用户提问时：

1. 问题也转成向量；
2. 在向量库里找最相似的片段；
3. 把片段交给 AI；
4. AI 基于片段回答。

---

## 5. 使用方法

### 方式 1：知识库内检索

入口：

> 知识库管理 → 选择知识库 → 检索

输入问题，系统返回：

- 命中的片段；
- 来源文件；
- 相似度；
- 元数据。

适合：

> 我想先看看知识库里有没有相关内容。

### 方式 2：统一检索

一次检索：

- 所有知识库；
- 长期记忆。

结果会：

- 合并；
- 按相似度全局排序；
- 标注来源类型。

适合：

> 我不确定资料在哪个库，先全局搜一下。

### 方式 3：知识库问答

入口：

> 知识库管理 → 知识库问答

流程：

1. 输入问题；
2. 选择 Top-K；
3. 系统先统一检索；
4. 把命中片段注入提示词；
5. AI 基于这些片段回答。

特点：

- 不需要 AI 自己反复调检索工具；
- 回答更聚焦于你的资料；
- 适合明确的“基于我的资料回答”场景。

### 方式 4：Agent 自动调用

在普通 AI 对话里，AI 可以自动调用知识库工具。

你可以直接说：

> 查一下我的知识库里关于半导体设备的内容。

> 结合我的研报库分析一下这家公司。

> 在我的交易规则知识库里找一下止损原则。

系统会：

1. 列出知识库；
2. 选择相关库；
3. 检索；
4. 基于结果回答。

### 方式 5：跨知识库 + 长期记忆统一回答

AI 可以一次检索：

- 多个知识库；
- 历史问答经验。

适合：

> 结合我以前的分析和现在上传的资料，一起判断。

---

## 6. 知识图谱

部分知识库支持构建知识图谱。

系统会用 LLM 从文档片段里抽取：

- 实体：公司、人物、机构、概念、指标、事件；
- 关系：投资、属于、竞争对手、供应商、客户等。

然后形成可视化图谱。

适合：

- 看产业链关系；
- 看公司关联；
- 看概念之间的连接；
- 辅助人工研究。

注意：

- 图谱构建是异步的；
- 节点数量有上限；
- 构建质量取决于文档质量和 LLM 抽取效果。

---

## 7. 注意事项

1. **知识库不是越大越好**
   - 一个库放一个主题，检索更准。
   - 例如“半导体研报”“交易规则”“个股资料”分开建。

2. **文件格式要正确**
   - 只支持纯文本和 Markdown。
   - PDF/Word 先转换。

3. **embedding 模型要匹配**
   - 中文资料建议用中文效果好的 embedding 模型。
   - 同一个库不要中途换模型。

4. **检索不到时先检查**
   - 文档是否向量化成功；
   - 问题是否太宽泛；
   - Top-K 是否太小；
   - 资料里是否真的有相关内容；
   - 切片是否把关键信息切碎。

5. **知识库适合“静态资料”**
   - 实时行情、新闻、龙虎榜 → 用内置工具。
   - 研报、笔记、规则、历史资料 → 用知识库。

# 五、MCP、技能、知识库三者怎么配合

| 能力 | 解决什么问题 | 类比 |
|---|---|---|
| 内置工具 | 查行情、财务、新闻、龙虎榜、资金流 | AI 的“眼睛” |
| MCP | 调外部系统、发消息、查企业 API | AI 的“手脚” |
| 技能 | 告诉 AI 按什么方法论做 | AI 的“操作手册” |
| 知识库 | 给 AI 提供私有资料 | AI 的“资料柜” |
| 长期记忆 | 记住历史问答经验 | AI 的“经验本” |
| 用户画像 | 记住用户偏好 | AI 的“用户档案” |

组合示例：

> 用“龙头战法”技能，结合知识库里的半导体研报，查今天龙虎榜，最后通过飞书 MCP 发到群里。

对应：

- 技能 → 分析方法；
- 知识库 → 研报资料；
- 内置工具 → 龙虎榜数据；
- MCP → 飞书发送；
- 长期记忆 → 参考以前类似分析；
- 用户画像 → 按你的风格输出。

# 六、建议的上手顺序

如果你要在这个项目里落地，建议按这个顺序：

1. **先配好 AI 模型**
   - 至少一条可用的对话模型；
   - 如果要知识库，再配一条 embedding 模型。

2. **再建知识库**
   - 先放最常用的研报、规则、笔记；
   - 验证检索和知识库问答效果。

3. **再导入技能**
   - 先从技能广场下载成熟技能；
   - 或自己写一个 `SKILL.md`；
   - 用 `/` 手动验证效果。

4. **最后接 MCP**
   - 先接一个简单的，例如飞书/钉钉；
   - 测试连接、启用、自然语言调用；
   - 再考虑把 MCP 绑定到技能。

5. **用 DeepAgents 做复杂任务**
   - 技能自动选择、MCP 动态检索、知识库检索、文件能力都在这个模式下最完整。

这样从“模型 → 资料 → 方法 → 外部工具”逐步搭建，最容易定位问题，也最容易看出效果。
